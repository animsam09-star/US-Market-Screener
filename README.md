# 미국 섹터 스크리너

**이미 오른 섹터를 따라가지 않고, 앞으로 오를 섹터를 찾기 위한 도구.**

두 축의 교집합으로 테마를 고른다.

- **촉매 축** — 왜 오를 이유가 있나 (9개 축)
- **미반영 축** — 왜 아직 가격에 없나 (4개 축)

촉매만 보면 결국 남들이 이미 산 걸 산다. 미반영 축이 그걸 막는다.

전 지표가 **무료 공공데이터**다: FRED · SEC XBRL · SEC 전문검색 · Federal Register ·
Yahoo Finance · BEA 산업연관표.

---

## 판별 방법

### 1. 테마가 자기 촉매를 먼저 선언한다

```yaml
- name: 방산·탄약
  thesis: 재고 소진분 보충 + 국방비 상향 — 예산이 확정된 다년 계약
  catalysts: [정책, 병목]      # 이 테마가 오른다면 이 축 때문이어야 한다
```

촉매 점수는 **선언한 축 안에서만** 나온다. 9개 축 중 아무거나 높은 걸 집으면
"왜 오르나"가 아니라 "무엇이 마침 높나"가 된다. 실제로 그랬다 — 방산이 1위였는데
점수를 만든 축이 ⑧재고와 ③신기술이었다.

선언 안 한 축이 강하면 **'예상 밖 촉매'** 로 따로 보여준다. 순위엔 안 넣는다.
철강이 좋은 예다: 주장한 캐펙스 고갈은 틀렸고(capex/감가상각 1.86배, 산업
생산능력 +0.9%) 실제로는 재고 바닥 90.9와 스프레드 65.8이 작동 중이다.
**틀린 이유를 반증하고 맞는 이유를 제시한다.**

### 2. 각 축은 주장 · 확증 · 기각 3요소로 판정한다

| | |
|---|---|
| **주장** | 관측 가능한 명제 |
| **확증** | 독립된 두 번째 데이터가 같은 말을 하는가 |
| **기각** | 같은 숫자를 만드는 *나쁜 이유*를 배제했는가 |

기각에 걸린 축은 **점수 0이 아니라 '기각 + 사유'** 로 화면에 남는다.
조용한 0점은 "신호가 약함"과 "논리가 틀림"을 구별하지 못하게 만든다.

예: 가동률이 높다고 다 공급 부족이 아니다. 생산능력이 줄고 생산도 줄었다면
수요가 늘어 가동률이 오른 게 아니라 **설비를 닫아서** 오른 사양산업이다.
`CAPUTL*`(가동률) 외에 `CAPG*`(생산능력)와 `IPG*`(생산)가 함께 필요하다.

### 3. 논지 성립 여부가 가장 중요한 출력이다

| 판정 | 뜻 |
|---|---|
| 논지 성립 | 주장한 축이 확증까지 통과 |
| 논지 미확증 | 축은 살아있으나 2차 증거 부족 |
| **반증 안 됐으나 신호 없음** | 축은 살아있는데 점수가 낮다. 논지가 틀린 게 아니라 **지금 작동 중이라는 증거가 없다** |
| 논지 일부 기각 | 기각 조건에 걸린 축이 있다 |
| 논지 미성립 | 주장한 축이 전부 죽었다 |

촉매 점수는 단순평균이 아니라 **최강 2개 축의 평균**이다. 테마는 보통 한두 축으로
오르고, 9개를 평균하면 강한 신호가 무관한 축에 희석된다.

전체 판별식은 **[설계_촉매판별.md](설계_촉매판별.md)** 참조.

## 쓰는 법

### 처음 한 번

```bash
pip install -r requirements.txt
```

BEA 산업연관표(고객군 자동 지정)를 쓰려면 [무료 키](https://apps.bea.gov/API/signup/)를
발급받아 `bea_key.txt` 에 한 줄로 넣는다. 키가 없어도 나머지는 다 돌아간다.

```bash
python check_key.py     # 키가 읽히고 실제로 통하는지 확인
```

### 실행

```bash
python run.py
```

`out/screener.html` 이 만들어지고 브라우저가 열린다.

| 옵션 | |
|---|---|
| `--theme 정유` | 이름에 '정유'가 들어간 테마만 |
| `--no-open` | 브라우저 안 열기 |
| `--refresh` | 캐시 무시하고 새로 받기 |

### 테마 추가·수정

`themes.yaml` 블록 하나를 복사해 고치면 된다. 파일 상단에 필드 설명이 있다.

핵심은 `customers:` 블록이다. **①낙수와 ④교체주기는 테마 자신이 아니라 테마의
고객을 재야 한다.** 전력기기가 오르는 이유는 전력기기 산업생산이 늘어서가 아니라
유틸리티·데이터센터의 설비가 늙고 증설이 밀려서다.

## 사내망에서 쓸 때 (중요)

다올 사내망은 SSL 검사 프록시를 쓴다. 인증서를 갈아끼우기 때문에 `certifi` 번들을
쓰는 도구(`curl`, `requests` 기본값)는 **전부 실패**한다 —
`CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain`.

Windows 인증서 저장소에는 사내 CA가 등록돼 있으므로, `truststore` 로 OS 네이티브
검증을 파이썬에 주입하면 해결된다. `screener/net.py` 가 이미 하고 있고,
`requirements.txt` 에 포함돼 있다.

설치 자체가 SSL 때문에 막히면:

```bash
python -m pip install truststore --trusted-host pypi.org --trusted-host files.pythonhosted.org
```

`git push` 가 같은 이유로 막히면 Windows 인증서 저장소를 쓰게 한다:

```bash
git config --global http.sslBackend schannel
```

GitHub Actions 러너는 사내망 밖이라 이 문제가 없다.

## 자동 갱신 · 외부 접근

`.github/workflows/update.yml` 이 평일 미국장 마감 후 하루 한 번 돌면서 대시보드를
다시 만든다. 결과는 두 곳에서 볼 수 있다.

- **GitHub Pages** — 어디서든 URL로 열람
- **Actions 아티팩트** — Pages를 안 쓰는 경우 `screener-html` 다운로드

필요한 저장소 시크릿 (Settings → Secrets and variables → Actions):

| 이름 | 필수 | 용도 |
|---|---|---|
| `BEA_API_KEY` | 선택 | 산업연관표 기반 고객군 자동 지정 |
| `SCREENER_UA` | 권장 | SEC 가 요구하는 연락처 포함 User-Agent. 없으면 403 위험 |

## 데이터가 막힐 때의 동작

클라우드 러너(GitHub Actions)에서는 SEC·Yahoo 가 데이터센터 IP 를 차단하는 일이
있다. 조용히 반쪽짜리 순위를 내놓지 않도록 세 겹으로 막아뒀다.

| 막히는 것 | 대응 |
|---|---|
| SEC 티커 목록 | `data/ticker_cik.json` 동봉본 사용 (거의 안 변하는 데이터) |
| SEC 재무 | `data/financials.json` 동봉 스냅샷 사용. **재무는 분기에 한 번 바뀌므로 매일 받을 이유가 없다** |
| Yahoo 주가 | Stooq 폴백 |
| 아무거나 통째로 | 대시보드 상단에 **결손 경고 배너** — 무엇이 왜 빠졌는지 표시 |
| 차단된 호스트 | 연속 4회 실패 시 회로차단. 이후 호출을 생략한다 (없으면 실행이 몇 시간짜리가 된다) |

재무 스냅샷은 분기 실적 발표 후(2·5·8·11월경) 사내망 PC 에서 갱신한다.

```bash
python export_financials.py
```

## 한계 (읽고 쓸 것)

- **컨센서스 추정치 리비전이 없다.** 무료로 구할 수 없어 SEC XBRL 기반 TTM 매출
  증가율의 가속도로 대신했다. 실제 리비전보다 2~3개월 늦다.
- **⑩ 대체·점유율 이전 축은 미구현.** 세부 품목별 출하 믹스가 필요하다.
- **⑧⑨ 재고·병목 축은 테마별 산업 시리즈를 지정해야 켜진다.** 전 제조업 총계로
  폴백하면 모든 테마가 같은 점수를 받아 순위가 무의미해지므로, 지정 없으면 끈다.
- **고객 티커는 자동으로 못 정한다.** BEA 산업연관표는 산업 단위이고 상장사 매핑이
  없다. 자동으로 채우는 건 ①낙수 축이 쓰는 `customers.series` 뿐이고,
  ④교체주기 축이 쓰는 `customers.tickers` 는 수동이다.
- 이 도구는 **후보를 좁히는 장치**이지 매수 판단이 아니다. 각 축의 '근거↗' 링크로
  원본을 확인하고 판단할 것.

## 회귀 테스트

```bash
python tests/run_tests.py
```

**판별 로직을 고치면 반드시 돌린다.** 새로 발견한 오류는 고치기 전에 케이스를
먼저 추가한다. 각 테스트에는 "무엇을 검사하나"가 아니라 **"무엇이 잘못됐었나"**
가 적혀 있다 — 그래야 나중에 이 제약이 왜 있는지 알 수 있다.

현재 12개 사고, 37개 단언. 네트워크를 쓰지 않는다.

| | 고정한 사고 |
|---|---|
| F1 | 미국 기업은 분기가 아니라 누적(YTD)으로 보고한다 — capex 가 15건만 잡혀 축 2개가 죽어 있었다 |
| F2 | 전 제조업 총계 폴백으로 8개 테마 촉매 점수가 전부 80으로 같아졌다 |
| F3 | BEA 는 메서드마다 Results 모양이 다르다 (dict vs list) |
| F4 | 최종수요(F02E 설비투자)가 60% 비중 1위 '고객'으로 잡혔다 |
| F5 | 접두 비교 방향이 반대라 항공기(3364)가 자동차(3361MV)로 매칭됐다 |
| F6 | 차단된 호스트 타임아웃으로 실행이 몇 시간짜리가 됐다 |
| F7 | 빈 시크릿이 기본값을 무력화해 User-Agent 가 비고 SEC 403 |
| F8 | 방산이 1위인데 점수를 만든 축이 무관한 재고·신기술이었다 |
| F9 | 10년 창이 코로나 재고 급증을 품어 현재를 과도하게 낮게 보이게 했다 |
| F10 | 언급 기업 4개사→5개사를 '+25% 확산'으로 읽어 56점을 줬다 |
| F11 | SEC 403 하나로 실행 전체가 죽었다 |
| F12 | 분기에 한 번 바뀌는 재무를 매일 원격에서 받고 있었다 |
